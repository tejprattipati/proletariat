# Read-only Canvas server adapter

This module is server-only. It is exercised against fictional fixtures and has not been verified with institution credentials. It exposes no write or coursework-submission API and invokes no model.

The lead owns protected connection/status/disconnect routes, encrypted credentials, workspace transactions, scheduled jobs, task upserts and report delivery. Import `CanvasIntegration`, `verifyCanvasConnection`, and adapter types from `index.ts`. Supply a durable per-owner `store`, a server-verified `getOwnerId`, current encrypted `getCredentials`, and `allowedOrigins`. `collect({resume?,runId?,maxPages?,timezone?})` returns `{snapshot,report,hasMore,apiCalls,modelCalls:0}`. `apiCalls` counts this invocation only. `report.id` is the sweep ID and remains stable during resume/replay. `snapshot.newTaskIds` and `changedTaskIds` are empty until the lead resolves canonical task IDs.

Connection input is explicitly supplied to the protected backend endpoint, never chat or a public fixture. Before persisting it, call `verifyCanvasConnection({baseUrl,token,ownerId},{allowedOrigins})`; this issues only `GET /api/v1/users/self/profile`. Persist the returned `accountId`, account label, normalized origin, owner, token and a fresh connection ID encrypted outside Git. No email matching is used. Each call checks owner/current connection before and after reads; a changed/disconnected connection cannot reuse its checkpoint. Reconnecting the same institution/account preserves stable provider identity while changing the grant checkpoint namespace. Disconnect and account changes must archive/invalidate old source context and disable jobs in the lead's workspace transaction.

Set backend `CANVAS_ALLOWED_ORIGINS` to an operator-approved comma-separated list of exact public HTTPS institution origins. This is the lead's environment variable; the adapter receives parsed `allowedOrigins` and reads no environment secrets itself. Arbitrary origins, IP/loopback hosts, credentials in URLs, redirects and cross-origin pagination are rejected. Operators must approve only genuine institution hosts. Supply `TOKEN_ENCRYPTION_KEY` and app identity/backend session configuration through the existing private deployment setup. Tokens are never frontend variables or returned in status. A Canvas institution must allow the user to create/use a read-only scoped personal access token or an institution-approved OAuth/developer token. A broad token is not made read-only at Canvas by this code; use institution-approved read permissions. The adapter itself sends GET requests exclusively.

Reads use active student enrollment, respecting Canvas course/section/term date filtering, and paginate courses, assignments, classic quizzes, discussion topics, modules and every module's items. Assignment requests explicitly enable `override_assignment_dates=true` and request the current user's submission, overrides and visibility. Canvas's user-effective `due_at`, `unlock_at` and `lock_at` are used; no base `all_dates` fallback is substituted. Exact timestamps and offsets remain in report items; task display date/time is converted to the workspace timezone. Missing/invalid effective dates or unknown submission facts are explicit gaps. A verified effective deadline remains available even when submission state is unknown; domain ingestion suppresses definite-overdue claims and automatic work blocks while completion is unconfirmed. Missing date facts remain coverage gaps and never invent a deadline. No-submission placeholders remain context; actual module reading/completion requirements generate deadline-free work. Submitted/pending-grading/graded/excused items are fulfilled provider obligations without asserting local completion or sending anything to Canvas.

Identity includes owner, host, selected account, course, kind and external ID. Quiz/discussion assignment IDs and resolved module links are provider-proven aliases; titles never merge identities. `SourceObligation.aliases` contains equivalent scoped source IDs paired with the same item ID, as required by domain ingestion. Aliases discovered without reading linked content are not counted as body/submission reads. Adapter coverage includes separate `metadataRead`, `contentRead`, and `submissionRead` counts; `read` counts actual extracted bodies. Unsupported, locked or unresolved content remains visible in family coverage.

Each invocation processes at most 5 pages by default (configurable 1–10), each response at most 2 MiB. A sweep is bounded to 5,000 pages/source records and 10 million extracted characters; descriptions are bounded to 40,000 characters. Sources, aliases, queue and applied-page cursor are committed together in one durable job record. A failed page stays resumable; successful families retain their last successful read. New/changed reports use the sweep's frozen prior identity baseline. Initial inventory is explicit; discoveries after earlier gaps are labeled uncertain publication timing. New module aliases alone do not produce new assignments. Partial sweeps never advance the exhaustive timestamp, delete unseen records, or infer source removal. Delivery retries must reuse the report ID.

Known coverage limits are reported, not silently declared exhaustive: inaccessible endpoints, unavailable student submission facts, unresolved graded quiz identities, locked descriptions, unsupported module requirements and truncation. Classic quiz discovery cannot prove completeness of New Quizzes or external-tool systems; assignments remain discoverable through the assignment API but unknown tool-specific obligations/status must be reported as gaps. Verify the institution's New Quizzes/external-tool access separately before claiming exhaustive institution coverage. Durable per-owner storage must be bounded/retained by the lead's data retention policy; complete sweep records intentionally remain available for delivery replay.

Official API references: [Courses](https://developerdocs.instructure.com/services/canvas/resources/courses), [Assignments](https://developerdocs.instructure.com/services/canvas/resources/assignments), [Quizzes](https://developerdocs.instructure.com/services/canvas/resources/quizzes), [Discussions](https://developerdocs.instructure.com/services/canvas/resources/discussion_topics), [Modules](https://developerdocs.instructure.com/services/canvas/resources/modules), [Submissions](https://developerdocs.instructure.com/services/canvas/resources/submissions), [Pagination](https://developerdocs.instructure.com/services/canvas/basics/file.pagination).

`createSyntheticCanvasAdapter()` from `synthetic.ts` is explicitly network-free, returns `synthetic:true`, `mode:demo`, and `realProviderCalls:0`, and captures mocked API calls. It is never a fallback for missing live configuration.

Authoritative `due_at:null` is emitted as `SourceObligation.dueDate:null` and `dueTime:null`, preserving explicit clearing through JSON checkpoints. Unknown/missing/partial dates omit both fields; domain ingestion keeps any earlier verified deadline and user corrections. Clearing the provider deadline does not clear a user-owned deadline override, and lifecycle history retains the transition.
